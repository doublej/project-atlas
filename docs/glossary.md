# project-atlas glossary

Canonical terms, used byte-for-byte across atlas-api, atlas-browser, atlas-picker and atlas-cli.
The root `CLAUDE.md` carries a one-line version of each; this is the full definition.

- **Project** — one scanned development folder. The core record (`name`, `slug`, `path`, `type`, `framework`, `runner`, `git`, `scripts`, `deploy`, `beads`, `domains`, `umami`, …).
- **slug** — kebab-case DNS label derived from a project's folder name (`.atlas` `slug` overrides it). Used to build its dev hostnames.
- **dev hostname** — a project's stable `<slug>.atlas.local.jurrejan.com` (LAN) / `<slug>.atlas.remote.jurrejan.com` (password-gated, WAN) address, brokered by the NAS Caddy (`caddy-porkbun`) that atlas pushes site blocks to via `atlas-api/src/lib/caddyDev.ts`. Registered on first `POST /api/run`, listed at `GET /api/hostnames`.
- **host** — one catalogued machine, identified by a `shared/hosts.json` id: `m2` (this Mac, the **primary**), `fractal` (Windows **satellite**, `C:/dev`), `ubuntu` (**deploy** target, `/home/jurrejan/development`). Every `Project` carries `host`. Not to be confused with `<slug>.dev.remote…`, which is the WAN half of a dev hostname *on this same Mac* — `host` is the machine axis, `remote` is the reachability axis.
- **isLocal** — present (and `true`) only on the primary host's projects. Its *absence* is what hides every action that touches a filesystem or a GUI, and `/api/*` write routes reject a non-local path with 400 regardless.
- **alsoOn** — the same project catalogued on another machine, derived at merge time by exact name match. Skipped when the name is ambiguous on the primary, so a link is never a guess.
- **host registry** — `shared/hosts.json`: the machines atlas catalogs, their roots and SSH aliases. The third registry, alongside actions and daemons.
- **service** — a permanent local web UI (atlas console, deckhand) that gets a dev hostname without being a project. Routed by `atlas-api/src/lib/services.ts` at daemon start and every 60s: `direct` to a wildcard bind, `bridge` for a loopback-only one — a forwarder on the LAN IP that accepts only the NAS — or `down`. Services share the project slug namespace in `.atlas-hostnames.json`; a collision is refused. `atlas.remote` is off unless the entry sets `remote: true` (atlas-api carries shell-exec routes), and then sits behind the service password, never the one handed out with dev previews.
- **service registry** — `shared/services.json`: `slug`, `name`, `port`, optional `daemon` label, `remote` and `host` — a short LAN name served next to `<slug>.atlas.local` (the console is `atlas.jurrejan.com`, covered by the NAS's `*.jurrejan.com` wildcard cert). Hand-curated; the fourth registry. Discovery of candidates is planned, not built (`.orchestrate/services-discovery.md`).
- **scan agent** — a bundled copy of the scanner (`bun run agent:build`) shipped to each remote host by `atlas hosts sync` and run over SSH. Its `--json` mode prints a `ProjectAtlas` on stdout and writes nothing.
- **domains** — the production domains a project publishes on, detected from its own files (CNAME, vercel/wrangler config, `package.json` homepage, `og:url`, robots.txt, env). Never fetched from a provider.
- **tags** — free-form labels on a local project (lowercase kebab), kept centrally in `~/dev/.atlas-tags.json` keyed by `relativePath` so tagging never dirties a repo. Merged onto `Project.tags` by `finalizeAtlas`; follow a folder through `/api/rename`/`/api/move` only. `atlas tags` (list · show · set/add/rm), `/api/tags`, a Tags facet + badges in the console, searchable in Raycast and the picker.
- **descriptions** — a project's written description, kept centrally in `~/dev/.atlas-descriptions.json` keyed by `relativePath` for the same reason as tags. An entry beats `.atlas` `description`, the manifest and the README's first line, which are the fallback in that order. Written by `PUT /api/description` (the console's description editor) and `atlas set description`; follows a folder through `/api/rename`/`/api/move` only.
- **agentInterfaces** — what a project offers an agent: `{ kind: 'mcp' | 'cli', name }[]`, always bound to the deepest project holding its source. Two passes: `detectAgentInterfaces` reads a project's own root (an MCP SDK dependency — `@modelcontextprotocol/sdk|server`, `mcp`/`fastmcp`, `rmcp`, `mcp-go` — makes an `mcp` entry; a bin is `cli` only when its entry point or README/CLAUDE.md/AGENTS.md mentions `--json` or a `<tool> prime` command); then `attachAgentInterfaces` (`agentRegister.ts`) adds what lives deeper — every bin in `~/.bun/bin`, `~/.local/bin` (uv tool receipts), `~/go/bin`, `~/.cargo/bin` built from the catalog (`*-mcp` names count as MCP, the rest need the same signal anywhere in their source) and every nested manifest with an MCP SDK. Its ripgrep runs `--no-ignore-vcs`: a nested repo (wallgen in pimpelmees) sits in its parent's `.gitignore`. `.atlas` `agentInterfaces` replaces both passes (`atlas set agentInterfaces "cli:x mcp:y"`, `[]` clears). An MCP entry carries `launch` (`command`, `args`, env *names* only, `from`) when atlas knows how a client starts it, best source first (`mcpLaunch.ts`): `.atlas` → a `~/.claude.json` registration (secret-looking args redacted) → an installed `*-mcp` bin → `<cli> mcp` → run from source (package bin via bun, `uv run`, `go -C … run .`, `cargo run`). The project's settings render it as `claude mcp add`, `.mcp.json` and Codex `config.toml` snippets. The **agent register** is all of them: `atlas agents`, the console's `/agents`, an MCP/CLI badge and facet on `/`.
- **umami** — the Umami analytics link: `websiteIds` found in the project's tracking snippets plus the `instance` base URL. Dashboard URL is `{instance}/websites/{websiteId}`. The scan never calls Umami; the project page's Umami section reads live statistics per website id through `/api/umami`, with the credentials `launchd/start.sh` exports from onenv `umami`.
- **claudeSetup** — a project's Claude Code situation: the MCP servers scoped to it (its `.mcp.json` plus any added with `claude mcp add`, and which of them are switched off) and what `.claude/` carries (agents, commands, skills, rules, hook events, which settings files exist). Counts and names, never file contents — `agentFiles` holds the CLAUDE.md/AGENTS.md token estimates, and claude-tree is where the files themselves are read. MCP on/off state comes from `~/.claude.json`, which is why only an explicit "off" is reported: approval for a project that has never been opened is written nowhere.
- **ProjectAtlas** — the full scan result: projects + folders + detected frameworks. The `/api/projects` payload shape.
- **Scanner** — the atlas-api module (`scanner.ts`) that walks `~/dev` and produces a ProjectAtlas. The source of truth for the Project shape.
- **cache** — `.atlas-cache.json`, the persisted ProjectAtlas (60s TTL, stale-while-revalidate). atlas-picker reads it directly.
- **scan config** — `.atlas-config.json` at the scan root: `maxDepth` (how deep the walk goes, default 3), `depth` (per-subtree limit, keyed by `relativePath` — also the only way to catalog a project that sits *inside* another project) `force` (`true` catalogs a folder the detectors ignored, `false` demotes one they got wrong and keeps walking through it) and `ignore` (glob patterns — a bare name matches at any depth and takes its subtree with it, a leading `/` anchors to the root; the walk skips those folders whole). Edited by hand or from the web console; per-project `.atlas` stays the place for everything about a project itself.
- **Framework / Runner / GitStatus / DeployInfo** — the typed enums/structs on a Project. Names must match byte-for-byte across consumers (see `.claude/rules/shared-types.md`).
- **flow** — a project's branch flow: `feature/*` → **integration** (`develop`) → **trunk** (`main`) → an annotated tag + GitHub release. No release branches. `Project.flow` carries the policy (`gitflow` opted in · `trunk` ours, not opted in yet · `external` someone else's repo · `local` no remote), the trunk and integration branch names, the owner of the **main repository** (origin), and a `drift` line when the current branch breaks the flow. Detected per repo; `.atlas` `flow` overrides it.
- **disk** — `atlas disk`, the disk-space manager (spec: `.orchestrate/disk-spec.md`, ported from `~/dev/_management/disk`). Local-only. The web console's `/disk` shells out to it and never reimplements an operation. Three levers: **archive** idle projects into one verified `.tar.zst` each (default iCloud Drive `Dev Archive/`), **clean** rebuildable folders found by a home-folder **scan** (risk `rebuildable` · `reinstallable` · `review`), **trim** tool caches with each tool's own clean-up. State lives in `~/Library/Application Support/atlas-disk/` (`ATLAS_DISK_HOME` overrides): settings, the last analysis/scan, and `operations.jsonl` — the **operation log**, append-only, a `start` fsync'd before every file change; a start with no end is an **interrupted operation** that only `atlas disk recover` may touch. **Version id** = `<category>/<project>@<YYYYMMDD-HHMMSS>`. Exit codes: 0 ok · 1 error · 2 nothing to do · 3 partly failed · 4 refused.
- **board** — `atlas board`, the agents' message board: one global append-only JSONL (`~/Library/Application Support/atlas-board/board.jsonl`) shared across every project and session. For thoughts, not programming — talk about code or the task is frowned upon there. Not the **agent journal** (`agent-log`), which is per repo and about the work.
- **action registry** — `shared/actions.json`: what project actions exist and when. Not "commands", not "buttons".
- **daemon registry** — `shared/daemons.json`: the launchd daemons atlas displays/manages.
- **consumer** — one of the three UIs reading the shared shapes: atlas-api, atlas-browser, atlas-picker.
- **web console** — atlas-api's own UI, one shell over seven routes — every route sits under the same nav band (`Nav.svelte`), which also carries the single theme toggle: `/` (projects, with host badges, hostname chips, `alsoOn` twins and the per-project settings dialog with its Hostname section), `/ports` (every listener on the Mac grouped by owner — project, service, docker, system — with localhost + hostname links, collisions inline and select-and-stop), `/processes` (the process snapshot as app rows grouped by project), `/system` (hosts, scanner config, daemons, services, port audit, hostname doctor), `/templates`, `/claude-tree`, `/disk` (every `atlas disk` operation — reads through `--json`, changes as jobs the page follows). Pages are built from the ui primitives in `atlas-api/docs/ui-primitives.md` (FeatureHeader, Table, Selection, SideNav, ConfirmDialog, Notice, toast, PageState, `http`); every page and SideNav section opens on a FeatureHeader — numbered eyebrow, serif title, one-line lede, legend of live figures + source.
- **write guard** — `atlas-api/src/lib/guard.ts`, run by `hooks.server.ts` on every request: a non-GET passes only from loopback (loopback `Host`, same-origin or no `Origin`) or through the NAS on a LAN console hostname (`atlas.jurrejan.com`, `atlas.atlas.local…`) with a matching `Origin`. `atlas.atlas.remote.jurrejan.com` (behind the service password `CADDY_SERVICE_AUTH_HASH`, never the dev-preview one) is read-only, and LOCAL_ONLY routes (iterm, finder, env-files, agent-files, claude-tree, ports/allocate, processes/log, `projects?dir=`) are refused there even for reads. Everything else is 403 `{ error }`, and no response may be framed (`frame-ancestors 'none'` / `X-Frame-Options: DENY`).
- **process snapshot** — `atlas-api/src/lib/processes/`: one `ps -axww`, the netstat socket list, `launchctl list` and sysctl in parallel, then one `lsof` (cwd + fd 1) for processes not met before; ~2s TTL. Behind `/processes`, `/ports`, `/api/ports/listeners` and `atlas ps|kill`. Commands are redacted server-side; the only environment variable ever read is `CLD_SESSION_NAME`. This Mac only — other hosts' processes are deckhand's.
- **process kind** — what a process is, by binary family or tool: `claude`, `codex`, `mcp`, `language-server`, `bun`, `node`, `deno`, `uv`, `python`, `cargo`, `rustc`, `go`, `dolt`, `beads`, `docker`, `caddy`, `ollama`, `shell`, `app`, `system`, `other`; `tool` names the tool inside (vite, next, wrangler, tsx, uvicorn, jupyter, tsserver…). Contract: `src/lib/processes/types.ts`, mirrored in `atlas-cli/src/processes.ts`.
- **app row** — one process group folded into the process doing the work (`uv run` → its `.venv` python, `bun run preview` → node vite), with summed CPU/RSS, its children expandable, a project, and flags `orphan` · `duplicate` · `idle` · `heavy`. `dev: true` rows are the default view; apps and system need `all=1`.
